You are working on the existing DevMarket React + Vite project.

Your job is to implement the remaining technical foundation needed to release the PUBLIC COMPONENT LIBRARY.

IMPORTANT: Do not redesign the existing application. Work with the current architecture, routes, components, CSS variables, Firebase setup, and Supabase database.

==================================================

1. CURRENT ARCHITECTURE
    ==================================================

DevMarket uses a HYBRID backend architecture.

FIREBASE:

* Firebase Authentication
* Firebase Firestore
* Firebase Hosting

Keep Firebase responsible for user/personal data:

* authentication
* user profiles
* settings
* favorites/saved items
* other user-specific data already implemented

DO NOT migrate these systems to Supabase.

SUPABASE:
Supabase PostgreSQL is responsible for shared DevMarket/library data:

* categories
* components
* tags
* component_tags
* templates

Supabase also already contains the future Builder foundation:

* projects
* project_pages
* project_components
* project_assets

DO NOT build the Builder yet.

14. BULK COMPONENT IMPORTER

Create a separate developer/admin import tool.

This tool is NOT part of the public DevMarket UI.

Its purpose is to allow us to generate a folder of components and automatically upload/register them in Supabase.

Support a structure similar to:

components/
navbar-modern/
component.jsx
preview.png
metadata.json

button-set/
    component.jsx
    preview.png
    metadata.json
card-grid/
    component.jsx
    preview.png
    metadata.json

Metadata should support:

{
“name”: “Modern Navbar”,
“slug”: “navbar-modern”,
“type”: “navbar”,
“category”: “Navigation”,
“description”: “A modern responsive navigation bar.”,
“tags”: [“navigation”, “responsive”, “modern”],
“is_vip”: false,
“status”: “published”
}

The importer should:

1. Read component folders.
2. Read metadata.
3. Find/create the category.
4. Create/update the component.
5. Find/create tags where appropriate.
6. Create component_tags relationships.
7. Register the code reference.
8. Register preview/resource information.
9. Report successes and failures.
10. Avoid creating duplicate records when run multiple times.

The importer must be safe to run repeatedly.

Do not put this importer into the public application.
